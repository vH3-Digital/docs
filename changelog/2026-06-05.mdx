A big week. The intelligence layer's full surface area is now public, along with the automation and agent-tooling around it.

## New features

### Sentinels API

Continuous monitors for emerging risks and revenue opportunities now have a public API. 13 operational sentinels (performance slips, site deterioration, SLA clusters, scheduling drift, repeat visits, and more) and 6 growth-opportunity sentinels are available, with per-tenant thresholds, exclusion filters, and result limits. Detection runs at near-zero AI cost.

[Sentinels API](/api-reference/sentinels) · [Sentinels guide](/guides/sentinels)

### Cases

A lightweight case management system for tracking multi-step operational workflows: escalations, complaints, follow-ups, and anything spanning multiple jobs. Cases support priorities, tags, due dates, participants, linked items, and an activity timeline, so the platform can open a case, link evidence, and route it to a team automatically.

[Cases API](/api-reference/cases)

### Teams

Teams group users and can be scoped to specific customers, sites, or entities, enabling access control and filtered views across the platform. Full membership management and entity scoping are now exposed via the API.

[Teams API](/api-reference/teams) · [Users and teams guide](/guides/users-and-teams)

### Email Triage and Email Ingest

Two new endpoints for inbound email automation:

- **Triage** classifies inbound emails by category, urgency, and sentiment against your tenant taxonomy, and returns a deterministic routing decision. Known FM portal senders short-circuit to direct ingest with no AI classification cost.
- **Portal Ingest** extracts structured job fields from emails sent by known FM portals (Verisae, Bellrock, Access Maintain, Greene King, plus tenant-specific overrides), resolves customers, sites, and job types against the graph, and returns a review or auto-create outcome.

[Triage API](/api-reference/triage) · [Ingest API](/api-reference/ingest) · [Email triage FAQ](/faq/email-triage)

### Connie API

Connie, the conversational assistant grounded in your full operational record, is now callable over HTTP. Sessions, citations, and tool-call outputs are exposed so you can verify provenance from your own UIs.

[Connie API](/api-reference/connie) · [Connie guide](/guides/connie) · [Agent observability](/guides/agent-observability)

### Pre-visit Briefings

Generate a structured pre-visit briefing and natural-language call opener for an engineer assigned to a job, with full site history, similar fault precedents, and equipment context. Designed for `onTheWay` and `scheduled` transitions.

[Briefings API](/api-reference/briefings)

### Weather

Forecast and historical weather lookups for coordinates, jobs, and sites, including an `outdoor_work_risk` summary (`low`, `moderate`, `high`) for scheduling and retrospective analysis.

[Weather API](/api-reference/weather)

### User Authentication (JWT)

Per-user login and JWT session management for interactive applications, customer portals, and custom front-ends. Users log in with email and password; tenants are resolved server-side, and the API key never leaves your back end.

[User authentication](/api-reference/user-auth)

### n8n community node

The official `n8n-nodes-vh3ai` community node is now published on npm. One unified credential covers both the BigChange API and the VH3 AI intelligence layer, and every operation is labelled in the dropdown so workflows can mix FMS calls with intelligence-layer calls. The node is marked `usableAsTool: true`, so n8n AI agents can call it without extra configuration. Works on self-hosted n8n, n8n Cloud, or a VH3-managed instance.

[n8n community node](/n8n-node)

### Agent Starter Kits

Drop-in configurations to make any AI tool fluent in the VH3 API from day one:

- `AGENTS.md` for general agent runtimes
- Cursor rules for the Cursor IDE
- MCP setup for Claude, Cursor, and other MCP-aware clients
- Claude Projects instructions
- Claude Skills
- n8n agent templates

[Agent Starter Kits overview](/agent-kits/overview) · [MCP setup](/agent-kits/mcp-setup)

### Native Integrations

Per-user and organisation-level integrations are now activated directly inside the platform with a single authentication step. No API keys to manage, no developer involvement. Accounting (including Xero), CRM, communication (including Slack), email, calendar, and storage tools all feed into the intelligence layer as additional context.

[Native Integrations](/native-integrations)

### Reports API

Eight automated report types, daily, weekly, and account-level intelligence, are now available via the API for scheduled delivery or on-demand generation.

[Reports API](/api-reference/reports) · [Reports guide](/guides/reports)

## Updates

- **Search** — semantic discovery across jobs, sites, customers, contacts, and worksheets is now exposed as a single endpoint, with relational, semantic, and structured retrieval combined in one call. [Search API](/api-reference/search)
- **Dashboard** — operational KPIs and headline metrics are available through a single dashboard endpoint for embedding in custom front-ends. [Dashboard API](/api-reference/dashboard)
- **BigChange API coverage expanded** — direct access to BigChange contacts, jobs, invoices, quotes, sales opportunities, purchase orders, notes, persons, resources, vehicles, stock, worksheets, and reference data is now documented end to end. [BigChange API](/api-reference/bigchange/overview)
- **Pricing calculator** — transparent, usage-based pricing is now visible before commit, with the platform fee covering all built-in AI and agentic consumption metered through your own model provider key. [Pricing](/pricing)
- **Technology Partners programme** — partner paths for software vendors, integration builders, automation consultants, implementation specialists, and sector experts are now open. [Technology Partners](/partners/technology-partners)

## Fixes

- **Sentinels: `customer_risk_escalation`** — late finishes are now counted only when strictly late (`endDeltaMins > 0`).
- **Sentinels: non-complete detection** — `repeat_failure_escalation`, `customer_risk_escalation`, and `customer_noncomplete_anomaly` now derive non-complete from `Job.status = completedWithIssues` for more accurate triggering.
- **Sentinels: `engineer_performance_slip`** — evidence now includes both `recentJobs` (the jobs that formed the triggering streak) and `latestJobs` (the latest context), making review and audit easier.
